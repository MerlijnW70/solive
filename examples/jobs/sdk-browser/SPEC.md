# Job: The SDK in a browser and a bundler

`@intent-engine/client` does not load in a browser. Eight files reachable from its root import `node:` modules (packages/client/src: confirmation.ts, job-specs.ts, ledger.ts, pinned-fetch.ts, public-host.ts, rpc-transport.ts, svm.ts, testing.ts). The root re-exports everything through `export *`, about two thousand names, so editors drown builders in internals and no change to the public surface is ever noticed. errors.ts imports the whole engine IDL JSON to name engine errors, so every bundle carries it. `@solana/kit` is a hard dependency, so an app can end up with two copies of kit. This job makes the SDK a good citizen of web apps and bundlers.

Read first: packages/client/package.json, packages/core/package.json, packages/client/src/index.ts, packages/core/src/index.ts, the eight files above, errors.ts, packages/core/idl.json and how it is generated (scripts/codegen.sh), scripts/pack-test.sh, the CLI and solver imports from `@intent-engine/client` and `@intent-engine/core`, and docs/sdk-client.md.

## Required

1. Nothing reachable from the roots of `@intent-engine/core` and `@intent-engine/client` imports a `node:` module or a Node-only package. Node-only features move to a `@intent-engine/client/node` entry (pinned fetch with its DNS and private-network checks, Ledger signing, anything using `node:crypto` hashes that web crypto does not replace); `svm` and `testing` stay Node entries. The root uses web APIs (`crypto.subtle`, `fetch`, `TextEncoder`). Where a root feature needs a Node capability, it takes it as an option, and the Node entry supplies the hardened default; the CLI and MCP keep every protection they have today.
2. Engine error names and messages come from a small generated module, written by the existing codegen and checked by its drift check, so no bundle carries the IDL JSON unless it imports it.
3. Both packages declare `sideEffects: false`, and `@solana/kit` becomes a peer dependency of client and core with the range they support, kept as a dev dependency for the repository.
4. The roots export an explicit list of names: the public API documented in docs/sdk-client.md and docs/sdk.md, the types those signatures use, and the error classes. Names only the CLI, solver or tests need move to a `@intent-engine/client/internal` (and core equivalent if needed) entry that docs/sdk-client.md says carries no stability promise.
5. An API report per package root (a committed text file listing every exported name with its kind and signature), generated by a repository script; lint fails when the exports differ from the committed report.
6. docs/sdk-client.md gets a short "In a browser" section: what works, what needs the Node entry, and how spec fetching behaves without the Node protections. Every new sentence is pinned by a test.
7. Tests for each change.

## Rules

- Follow `CONTRIBUTING.md`: no code comments, nothing bypassed. Do not change the program or the Rust crates. Keep TypeScript files under about 500 lines.
- packages/cli, packages/solver and packages/multisig keep compiling and passing; adapt their imports.

## Acceptance

1. With the patch applied to `main` at the commit the delivery names: `cargo test --workspace`, `bash scripts/ts-test.sh`, `bash scripts/lint.sh` and `bash scripts/pack-test.sh` all pass.
2. A test bundles a small app that imports the client root with esbuild for the browser platform, no Node polyfills and nothing external: the build succeeds, the bundle names no `node:` module, holds no IDL JSON, and running it in a fresh `vm` context that has only web globals (`fetch`, `crypto`, `TextEncoder`, `TextDecoder`, `URL`, `console`) creates a client and parses an amount.
3. A second bundle that imports one small helper from the client root stays under a size budget the test states, showing tree shaking works.
4. pack-test installs the packed packages next to a single kit and shows one copy of kit in the tree.
5. Lint fails when the judge adds an export to a root without updating its API report, and the bundle test fails when the judge adds a `node:` import to a root file.

## Deliver

One `git format-patch` file. Announce its sha256 to the judge.
